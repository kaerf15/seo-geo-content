# 写作核心

## 通用回路

1. 只选一个目标：
   - 承接转化
   - 解释教育
   - 品牌判断
   - 分发引流
   - 激发互动
2. 先出候选：
   - 3 个标题
   - 2 个开头
   - 1 个 CTA
3. 只保留一条主线：
   - 问题 -> 结论 -> 证据 -> 行动
   - 冲突 -> 反转 -> 方法 -> 行动
   - 观点 -> 论证 -> 对比 -> 建议
   - 清单 -> 解释 -> 避坑 -> 行动
4. 写完只问 3 个问题：
   - 像这个平台原生内容吗？
   - 10 秒内能看懂价值吗？
   - 读完知道下一步做什么吗？

## 平台速记

- `landing_page`：承接页；价值前置、证据前置、CTA 明确；不要写成博客
- `own_blog`：观点长文；有判断、有边界、有案例；不要资料搬运
- `xiaohongshu`：经验帖；首句抓人、场景感、可收藏；不要机构口吻
- `zhihu`：专业回答；先给结论、逐条论证；不要无出处断言
- `wechat`：私域长文；开头有钩子、结尾有承接；不要平铺直叙
- `wechat_video`：微信短视频；先给结果、轻承接私域；不要公域爆款腔
- `douyin`：公域短视频；前 2 秒抓人、节奏更快；不要长铺垫
- `juejin`：开发者社区文；解法前置、步骤清楚、坑点明确；不要产品软文
- `linkedin`：B2B 观点；反共识、第一人称、数据加 mini-case；不要鸡汤
- `medium`：分析长文；thesis、框架、证据推进；不要纯 listicle
- `substack`：newsletter 长文；人味更强、订阅承接更自然；不要通用博客腔
- `hackernoon`：技术媒体文；角度更锋利、判断更强；不要普通教程腔
- `csdn`：技术文章；问题、解法、步骤、避坑；不要品牌博客腔
- `cnblogs`：开发者博客；结论、过程、取舍、踩坑；不要品牌长文腔
- `baijiahao`：搜索分发文；标题答题、首段直答、FAQ 清楚；不要普通博客直贴
- `toutiao`：信息流长文；判断前置、现象推进、建议收束；不要空观点
- `devto`：开发者文章；实操、代码、边界；不要产品页腔
- `quora`：英文问答；先答再解释、CTA 要软；不要品牌软文
- `bilibili`：知识向视频；解释更完整、节奏更稳；不要纯切片腔
- `twitter`：英文线程；首条最强、每条独立、节奏锋利；不要长文切条
- `tiktok`：国际短视频；前 1-2 秒停滑、画面切换快；不要广告片感
- `youtube`：英文视频；promise 清楚、解释完整、CTA 单一；不要假 hype
- `twitter_thread`：线程；每条独立成立、首条最强；不要长文切条
- `short_video`：口播脚本；前 3 秒、画面感、CTA 干净；不要超长铺垫

## 共通禁区

- 开头无钩子
- 有结构，没推进
- 所有平台像同一篇换壳稿
- CTA 太硬或太弱
- 有数字，没说服力
