# 多平台改编

同一主题发多个平台时：**每个平台一个 `output/<主题>-<platform>.md`**，禁止一份正文改标点糊弄。

## 改编原则

| 保留 | 重写 |
|------|------|
| 核心判断与事实依据 | 钩子、语气、篇幅 |
| 可核对数据与出处 | 结构、CTA 入口 |
| 品牌/产品实体名 | 标题公式、标签/话题 |

## 形态映射

```
长文（知乎/微信/百家号/头条）
  ├→ 短帖（小红书）：抽 1 个场景 + 3 条清单 + 口语 CTA
  ├→ 线程（Twitter）：抽 5–8 个独立判断，每条可单读
  ├→ 短视频（抖音/视频号）：抽 1 个反常识钩子 + 1 个结论 + 1 个例子
  └→ 开发者（掘金/CSDN）：抽操作步骤与代码，去掉营销铺垫

Landing / Own Blog（canonical）
  └→ 其它平台只摘「首段直答 + 某一节的论点」，FAQ 不整段复制
```

## 执行顺序（推荐）

1. 先写 **canonical** — `landing_page` 或 `own_blog`（信息最全、FAQ 最完整）
2. 再改 **深度长文** — `zhihu` / `wechat`（展开论证链）
3. 最后改 **短形态** — 小红书、Twitter、短视频（只留一个记忆点）

## 各平台从 canonical 抽什么

| 目标平台 | 从 canonical 抽取 |
|----------|-------------------|
| `xiaohongshu` | 首段直答 → 标题灵感；FAQ 选 1 条变场景故事 |
| `zhihu` | 全部 `##` 展开；FAQ 变「常见问题」节 |
| `wechat` | 论证链 + 行动清单；语气改订阅内参 |
| `douyin` | 首段直答 → 2–10s 口播；一个 FAQ → 例子 |
| `twitter` | 每个 `##` 首句 → 一条推文 |
| `juejin`/`csdn` | 「怎么做」章节 + 代码；去掉品牌铺垫 |

## 禁忌

- 同一标题跨平台复制（各平台标题公式不同）
- 长文直接截断当短帖
- 无事实依据时各平台**分别编造**不同数据
