# 掘金文章

> 解法前置的技术社区文，步骤与代码要密。

产出格式 → [formats.md](../formats.md) + [_dev_article.md](./_dev_article.md)

## 约束

- **篇幅**：1000–2400 字
- **标题**：≤80 字
- **语气**：developer-community, practical, concise
- **忌**：产品宣传腔；无实操细节
- **结构**：结论 → 步骤 → 代码/命令 → 坑点

## 标题公式

- `{技术栈} {问题} 的 {N} 种解法对比`
- `用 {工具} 解决 {具体报错/场景}`
- `{场景}下 {方案} 实践笔记`

## 分发要点

- **标签**：选 2–4 个技术标签，与正文栈一致
- **代码块**：可运行；注明版本号
- **封面**：代码截图或架构图，少纯文字
- **SEO**：标题含搜索问题（报错码、库名、场景）

## 发布 checklist（不写进 output）

- [ ] 标题 ≤80 字；含「先给结论」节
- [ ] 至少一个代码块或命令序列
- [ ] 坑点节 ≥2 条
