# 博客园文章

> 工程师复盘：多写取舍与「为什么」。

产出格式 → [formats.md](../formats.md) + [_dev_article.md](./_dev_article.md)

## 约束

- **篇幅**：1000–2500 字
- **标题**：≤80 字
- **语气**：developer-first, reflective, practical
- **忌**：品牌文案腔；只有结论无过程
- **结构**：结论 → 背景/为什么 → 步骤 → 取舍与坑点

## 标题公式

- `{项目/场景} 复盘：{关键取舍}`
- `为什么我们在 {场景} 选了 {方案}`
- `{技术决策} 的记录与反思`

## 分发要点

- **过程感**：写「试过什么、为什么否」比只写最终方案更有信任
- **代码**：关键片段即可，完整仓库链到参考来源
- **分类**：dotnet/ai 等频道明确，便于订阅读者
- **忌**：营销软文口吻 — 博客园读者对广告敏感

## 发布 checklist（不写进 output）

- [ ] 标题 ≤80 字
- [ ] 有「为什么」而不仅是「怎么做」
- [ ] 参考来源可点击
