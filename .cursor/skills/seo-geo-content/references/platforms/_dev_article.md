# 开发者长文

**适用**：`juejin` `csdn` `cnblogs` `devto`  
**数值约束**：各平台 key → [platform_rules.json](../../rules/platform_rules.json)

## 产出结构（中文平台）

```markdown
# {标题}

> {帮谁解决什么 — 一句话}

## 先给结论

- **场景**：…
- **推荐**：…
- **不适用**：…

## 环境 / 前置

- OS / 版本 / 依赖

## {做法}

{说明 + 代码块}

## 坑点与边界

1. …

## 参考来源

- [来源](url)
```

## 产出结构（devto）

同上，章节名可用英文：`Conclusion` / `Gotchas` / `References`

## 写作要点

- 结论节：读者 30 秒内能决定要不要继续
- 代码可复制；注释说明非显而易见处
- 坑点写真实失败场景，不写「暂无」
- 标题 = 问题；H2 = 子问题
- 忌：YAML 过程字段、发布元数据块（`## 先给结论` 等是正文结构，保留）
