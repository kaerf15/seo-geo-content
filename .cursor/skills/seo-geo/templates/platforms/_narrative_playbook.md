# 叙事原型手册（`_narrative_playbook.md`）

> 本文件**不是一个平台骨架**，它是 Agent 在 Step 3 写每一篇内容前的**必经中间步骤**：先在 `.workspace/narrative_<platform>.md` 里写出"从 facts 转译到该平台叙事原型"的一张牌，再开始填骨架。
>
> 目的：解决原设计里"同一套事实 → 换骨架填充 → 文风全平台趋同"的病。骨架只管结构硬约束（字数/Schema/FAQ 条数），**叙事层**管"这篇为什么值得一个人读到最后"。
>
> 本文件只由 Agent 读；不落盘到 `deliverables/`。SSOT 阈值不变动，叙事层只加"视角/原型/转译前后对照"三件事。

---

## 为什么需要这一层

一个 facts.md 里的事实，比如"我们 12 年做出口、欧洲客户占 70%、MOQ 500"，在：

- **landing_page** 上应是 *权威声明*（第三人称、数据前置、Schema 结构化）
- **xiaohongshu** 上应是 *第一人称踩坑史*（我自己当年怎么踩、怎么跑通、怎么判定靠谱工厂）
- **zhihu** 上应是 *专家拆解*（把"MOQ 500"拆成"为什么这个门槛对中型买家合适、对初创买家不合适"的行业洞察）
- **linkedin** 上应是 *反共识洞察*（12 年积累证伪了"大订单一定好做"这条假设，现实是……）
- **twitter_thread** 上应是 *结论流*（每条一个锋利观点，N/ 开头）
- **short_video** 上应是 *口播钩子 + 冲突*（前 3 秒必须制造一个反差）

如果 Agent 跳过这一层直接填骨架，结果就是同一份事实被"翻译"成风格均质的多平台稿——合规但不打人。

## 叙事原型（9 种，与平台骨架一一对应）

### 1. Authority Declaration（权威声明）—— landing_page

- **视角**：第三人称（品牌口吻）
- **节奏**：结论前置 / 数据前置 / 证据链就近 / 无铺垫
- **情感层**：克制、专业、不煽动
- **语言特征**：陈述句多于疑问句；"我们提供 X，基于 Y 数据，支持 Z 场景"
- **禁区**：个人感受、情绪词、"曾经/后来" 类叙事线
- **从 facts 转译的示例**
  - facts：MOQ 500
  - 翻译：**不写**"我们 MOQ 是 500"；**写**"适合单款年采购 500 件以上的中型买家"——把"门槛"翻译成"适配条件"

### 2. Pillar Explainer（支柱讲解）—— own_blog

- **视角**：作者第一人称（专家/从业者，不是品牌代言人）
- **节奏**：先给主张 → 展开证据 → 对比/案例 → 给判断
- **情感层**：有观点、有边界（"在 X 情况不适用"）
- **语言特征**：允许"我认为 / 从我们过去 3 年的数据看"；问题式小标题
- **禁区**：纯数据堆砌、无立场的综述
- **从 facts 转译的示例**
  - facts：欧洲客户占 70%
  - 翻译：**写**"为什么我们把欧洲定为主战场——过去 3 年我们测试过 5 个区域市场……"（把占比翻译成战略选择的复盘）

### 3. First-Person Pit Story（第一人称踩坑史）—— xiaohongshu

- **视角**：一个普通"我"，不是老板
- **节奏**：钩子（冲突/惨/反转）→ 我做了什么 → 我发现了什么 → 你可以抄作业
- **情感层**：真诚、不装、有吐槽但不扣帽子
- **语言特征**：短句、emoji 点缀、"先说结论" 前置、自拍口吻
- **禁区**：机构化/说明书式、硬广、过度专业术语
- **从 facts 转译的示例**
  - facts：12 年出口经验、认证齐全
  - 翻译：**不写**"12 年经验值得信赖"；**写**"我对比了 20 家工厂才明白怎么看验厂报告——这 3 个细节 90% 的新卖家都漏了"

### 4. Expert Dissection（专家拆解）—— zhihu

- **视角**：中立专家 / 行业观察者
- **节奏**：3 条以内的结论先行 → 逐条拆证据 → 给可执行清单
- **情感层**：冷静、有据可查、允许反驳主流观点
- **语言特征**：引用来源、"从 X 报告看 / 按 Y 标准"；问题式小标题
- **禁区**：抖机灵开头、无出处断言、情绪化
- **从 facts 转译的示例**
  - facts：70% 欧洲客户
  - 翻译：**写**"为什么中国出口商的"欧洲依赖"是机会不是风险——从三个数据维度拆解"

### 5. Serialized Insider（系列内参）—— wechat

- **视角**：私域主理人（写给订阅者看）
- **节奏**：痛点钩子 → 3–5 个小标题 → 每节 1 数据 1 案例 → 行动清单 → CTA
- **情感层**：克制但有温度；"我们"与"你"双视角
- **语言特征**：避免标题党；允许系列化（"这是我们出口系列的第 3 篇"）
- **禁区**：口水开篇、情绪化结论
- **从 facts 转译的示例**
  - facts：MOQ 500 + 欧洲占比 70%
  - 翻译：**写**"为什么我们把 MOQ 从 200 调到 500——一次战略复盘"（用私域信任讲策略决策）

### 6. Contrarian Insight（反共识洞察）—— linkedin

- **视角**：第一人称（我/我们），B2B 同行视角
- **节奏**：第 1 行抛一个反共识 → 一段 context → 1 个具体数字 → 1 个 mini-case → 3–5 条 takeaway
- **情感层**：自信、锐利、不妥协
- **语言特征**："I've been seeing… / after 12 years doing X, here's what I learned"
- **禁区**：泛泛口号、长段落（超过 3 行）、无 takeaway
- **从 facts 转译的示例**
  - facts：12 年出口 + 70% 欧洲
  - 翻译：**写**"Everyone says diversify your export markets. After 12 years, I disagree—here's what 70% EU concentration actually bought us."

### 7. Analytical Essay（分析长文）—— medium

- **视角**：分析师 / 写作者
- **节奏**：副标题 + TL;DR 前置 → 3–4 节主题式展开 → 每节 1 数据 → 框架/清单收尾
- **情感层**：分析、思辨、不急着给结论
- **语言特征**：conversational 但 evidence-first；小标题可以是观点而非问题
- **禁区**：listicle-only（只堆列表无深度）、无出处断言
- **从 facts 转译的示例**
  - facts：MOQ 500 合规欧洲
  - 翻译：**写**"The MOQ Paradox: Why Lower Is Not Always Better For Growing Importers"（把具体数字升维到一个概念/框架）

### 8. Crisp Thread（锋利线程）—— twitter_thread

- **视角**：第一人称专业号
- **节奏**：1/ 一句话结论钩子 → 2/~N-1/ 一条一个锋利观点（每条 ≤ 280 字符）→ N/ CTA
- **情感层**：决断、punchy、无铺垫
- **语言特征**：一条一句话；数字/对比/冲突穿插；避免术语堆砌
- **禁区**：情绪大字报、连续两条讲同一件事
- **从 facts 转译的示例**
  - facts：12 年 + 70% EU
  - 翻译："1/ Most exporters fear market concentration. Ours saved us. Here's why." → 后续每条一个数据点

### 9. Hook-Cut-Cue（钩子-切-行动）—— short_video

- **视角**：屏幕里的那个"我"或画外音
- **节奏**：0–3s 钩子（问题/数字/反差）→ 3–30s 核心结论（≤3 条）→ 30–70s 例证/演示 → 70–90s CTA
- **情感层**：口语、节奏快、首句必须抓人
- **语言特征**：口播 + 字幕对齐；画面有指引；无大段铺垫
- **禁区**：超长 intro、纯口播无画面
- **从 facts 转译的示例**
  - facts：验厂 3 个细节
  - 翻译：0–3s "90% 的新卖家验厂漏了这 3 个" → 3–30s 分别列 → 30–70s 展示文件样例 → 70–90s "私信领验厂 checklist"

## Agent 的使用步骤（写在 SKILL.md Step 3 里）

对每一个启用平台（Top 3 + landing_page），在填骨架 **之前**：

1. 在对话或 scratchpad 中输出一段"叙事转译牌"：
   ```
   平台：<platform>
   原型：<原型编号 + 名称>
   视角与情感：<一句话>
   从 facts 提取的 3–5 个事实块：
   - 事实 A → 转译为 <叙事化表达>
   - 事实 B → 转译为 <叙事化表达>
   - 事实 C → 转译为 <叙事化表达>
   本篇独特的锋点（区别于其他平台的一句话）：<...>
   ```
2. 这张牌可以作为段落直接写进 `.workspace/narrative_<platform>.md`（可选，不强制落盘）
3. 然后再打开平台骨架 `platforms/<platform>.md` 填内容——填的时候**不允许**把事实块按"列表 → 改写"的方式机械转成骨架条目，必须遵循叙事层确定的原型。

## 差异化检验（骨架内自检）

每份 deliverable 写完后，Agent 自问 3 个问题，有 1 个答"否"就回去重写：

1. 把本篇开头 3 段抹掉平台标识/格式差异，和 landing_page 开头放一起，能分辨出是两个平台吗？
2. 本篇的"锋点"（一句话独特主张）在其他平台的稿里复用了吗？若复用了，是否换了视角和叙事原型？
3. 本篇的叙事原型是否和平台匹配？（linkedin 上写 Authority Declaration、xiaohongshu 上写 Analytical Essay 都是错配）
